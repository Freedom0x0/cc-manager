# code-mentor Session Resume — 工作续接

**日期**: 2026-08-01
**作者**: brainstorming skill(对话驱动)
**目标仓库**: `~/.claude/skills/code-mentor/`(用户级 skill,master 分支 PR 流程)
**关联项目**: cc-session-manager(本仓库,仅作 spec 落地点)

---

## 1. 问题

code-mentor v2.0 现有能力(4 步节奏、5 角色、老项目安全模式、Bug 库、DECISIONS、JOURNAL、findings、与其他 skill 协作)全是**会话内**能力。**会话边界**没有覆盖:

- 用户一天工作结束 / 关电脑 → 下次开新 session → 说「继续上次」→ Claude 什么都不记得 → 工作断在中间
- 现有 JOURNAL.md 是「每次改动 1 行」(代码:行号 + 为什么),粒度太细,**会话维度**的状态没记录
- 现有 DECISIONS.md 是决策日志,不覆盖进行中但未决策的事
- 现有 mem-search 是 claude-mem 全局跨 session 库,但 code-mentor 写的本地档案没跟它打通(也不应该打通,mem-search 是全局检索,不是项目续接)

**用户原话**:
> 「我说『本次会话结束』,code-mentor 帮我把本次会话总结沉淀;我重开会话说『继续工作』,code-mentor 读当前项目的记忆接着工作,**能保证工作不中断**」

## 2. 设计目标

新增 `Session Resume` 能力,**会话边界**两端各做一件事:

- **写侧**:用户口令触发 → Claude 从对话上下文提炼 4 字段进度 → 用户确认 → 落盘
- **读侧**:用户口令触发 → Claude 读最新快照 → 报 1 句话进度摘要 → 等用户决定要不要进 4 步

## 3. 范围与非目标

### 3.1 范围内

- 新增 `Session Resume` 章节(SKILL.md 内)
- 新增触发词:写 3 个 + 读 2 个
- 新增 6 个测试 case(tc14-tc19,CASES.md)
- 新增文件系统路径:`session-snapshot.md` + `session-snapshots/`

### 3.2 非目标(YAGNI)

- ❌ **不**接 claude-mem / mem-search —— 用户没要求,且语义不同(全局检索 vs 项目续接)
- ❌ **不**支持多项目同时续接 —— 用户明确选「只记当前项目」
- ❌ **不**自动触发(定时、轮询、心跳)—— 用户明确选「口令触发」
- ❌ **不**自动进 4 步 —— 用户明确选「等用户点头才进」
- ❌ **不**主动提示打快照 —— 用户明确选「避免打断心流」
- ❌ **不**写进项目目录 —— 维持现有「运行时档案一律不写进项目目录」红线
- ❌ **不**做历史快照清理 —— 用户选「无限保留,自己定期清理」

## 4. 架构

会话边界能力,**与现有 4 步节奏并列**,不进任何一步内部:

```
会话边界(Section Resume,新增)
├─ 🔴 WRITE 侧(用户口令)
│  「本次会话结束」「今天工作结束」「收工」「先到这」 → 调起
│  ├─ Claude 从对话上下文提炼 4 字段草稿
│  ├─ 🔴 ASK:展示草稿 + 「确认保存吗?」(沿用改文件确认红线)
│  └─ 落盘(snapshot + 历史归档)
│
└─ 🔴 READ 侧(用户口令)
   「继续工作」「接着上次」「接上次」 → 调起
   ├─ 读 session-snapshot.md
   ├─ 不存在 → 「没找到上次快照,直接开始」→ 进原 4 步
   └─ 存在 → 🔴 输出 1 句话进度摘要,不主动详细报告
       ↓
      用户:「详细说说」→ 展开剩余 3 字段
      用户:「嗯,继续 A」→ 进原 4 步(把 A 当作任务名)
```

### 4.1 4 字段

| 字段 | 类型 | 例子 |
|---|---|---|
| **进度** | 一句话 | 「调试 src/foo.ts:42 的 Promise rejection」 |
| **未完成** | bullet 列表,≤3 项 | 「- [ ] 改 fetchUser 加 timeout\n- [ ] 跑测试验证」 |
| **关键文件** | `文件:行号`,≤5 个 | 「src/foo.ts:42\nsrc/api.ts:88」 |
| **下次起手** | 一句话 | 「重看 fetchUser 是否真的没 timeout,然后加」 |

### 4.2 写入路径(WRITE)

```
用户:「本次会话结束」
  ↓
Claude:从对话上下文提炼 4 字段草稿
  ↓
Claude:🔴 展示草稿 → 问「确认保存?」
  ├─ 用户:确认
  │   1. 检查 ~/.claude/code-mentor/<hash>/session-snapshot.md 是否存在
  │   2. 存在 → mv 到 session-snapshots/<旧文件 mtime ISO>.md
  │   3. 写新 session-snapshot.md
  │   4. 报「下次说『继续工作』可续接」
  ├─ 用户:拒绝 / 改 → Claude 修订草稿 → 再问(最多 3 轮,3 轮后放弃)
  └─ 用户:跳过 → 不落盘
```

### 4.3 读取路径(READ)

```
用户:「继续工作」
  ↓
Claude:读 session-snapshot.md
  ├─ 不存在 → 「没找到上次快照,直接开始」→ 进原 4 步
  └─ 存在 → 报「进度」字段(1 句话)
       ↓
      用户:「详细说说」→ 展开剩余 3 字段
      用户:具体指令 → 进原 4 步(把指令当任务名)
      用户:沉默 / 「嗯」 → 不主动进 4 步,等具体指令
```

## 5. 文件系统

```
~/.claude/code-mentor/<目录名-哈希6位>/
  project.md                  # 现有
  conventions.md              # 现有
  findings.md                 # 现有
  DECISIONS.md                # 现有
  session-snapshot.md         # ← 新增(每次「收工」确认后落盘,永远是最新)
  session-snapshots/          # ← 新增目录(历史快照,只增不改)
    2026-08-01T17-30.md
    2026-07-30T14-12.md
  notes/
    JOURNAL.md                # 现有
```

### 5.1 两套文件的语义

- **`session-snapshot.md`** = 「上次」指针,总是最新;每次新「收工」覆盖
- **`session-snapshots/<ISO>.md`** = 全部历史,只增不改,**无限保留**

### 5.2 不进 .gitignore

`~/.claude/code-mentor/` 在用户家目录,不在任何 git 仓库里,**无需 .gitignore**。

## 6. 触发词

### 6.1 写入口令(4 个)

- 「本次会话结束」
- 「今天工作结束」
- 「收工」
- 「先到这」

### 6.2 读入口令(3 个)

- 「继续工作」
- 「接着上次」
- 「接上次」

### 6.3 不触发的模糊词(写明避免误判)

- 「先休息一下」「我先关电脑」—— 不触发写,等用户明确
- 「上次」单独说 —— 不触发读,太模糊

## 7. 错误处理

| 场景 | 现象 | 兜底 |
|---|---|---|
| **写盘失败**(权限 / 磁盘满) | `writeFileSync` 抛 EACCES / ENOSPC | 错误完整贴出;**草稿先 echo 给用户**让 ta 自己复制保存 |
| **读快照失败**(文件损坏 / 半写) | 解析不出 4 字段 | 「上次快照读不出来(可能写了一半),重写一份新的?」,**不静默忽略**,不假装读到 |
| **「继续工作」时多个快照存在** | `session-snapshots/` 有 N 份 + `session-snapshot.md` 是最新 | 只读 `session-snapshot.md`,**不动历史**;用户问「上次上次呢」才列 `session-snapshots/` 目录 |
| **对话太短 / 没改东西,提炼不出 4 字段** | 「进度」字段空 | 🔴 **不强行写空快照**,问「这次没改什么,要记一笔空快照吗?」,用户拒绝则跳过不落盘 |
| **确认 3 轮用户都拒绝** | 草稿被拒 3 次 | 收尾:「那我先不保存,等你确定后再来」,**不强行保存** |
| **空 session-snapshots/ 目录** | 用户首次「收工」 | 自动 `mkdir -p session-snapshots/`,无需用户手动建 |

## 8. 红线对齐

不与现有红线冲突,补一条新规则:

| 红线 | 一致性 |
|---|---|
| 改文件要确认 | ✅ 写侧「确认保存吗」复用 |
| 不强推 | ✅ 草稿被拒 3 轮不强存 |
| 不静默吞错 | ✅ 读失败写失败都明说 |
| 不编造内容 | ✅ 「提炼不出 4 字段」就问,不强写 |
| 不写进项目目录 | ✅ 路径仍是 `~/.claude/code-mentor/<hash>/` |
| 不主动(避免抢方向盘) | 🆕 「会话结束前自动写快照吧」—— 错。用户口令触发,Claude 不主动 |

## 9. 测试

新增 6 个 tc 到 `tests/CASES.md`:

| tc | 场景 | 预期 |
|---|---|---|
| **TC14** | 「继续工作」+ 无快照 | 报「没找到上次快照」,立即进 4 步 Clarify |
| **TC15** | 「继续工作」+ 有快照 | 报 1 句话摘要(进度字段),**不展开** |
| **TC16** | 「继续工作」 + 报完摘要 + 「详细说说」 | 展开剩余 3 字段 |
| **TC17** | 「本次会话结束」+ Claude 出草稿 + 用户确认 | 落盘 `session-snapshot.md` + 旧快照 mv 进 `session-snapshots/` |
| **TC18** | 「本次会话结束」+ Claude 出草稿 + 用户拒绝 3 次 | 不落盘,报「先不保存」 |
| **TC19** | 「先休息一下」(模糊词) | **不触发**,正常走原 4 步 |

每个 tc 的 assert 形式跟现有 tc01-tc13 一致:`given / when / then / assert`。

### 9.1 手动 e2e 验证

- 在某个真项目触发 mentor 模式 → 跑 1-2 个改动 → 说「收工」 → 确认 → 看 `~/.claude/code-mentor/<hash>/` 有新文件
- 新 session 说「继续工作」 → 看 Claude 报 1 句话

## 12. 风险

- **对话上下文质量影响草稿质量** —— Claude 提炼 4 字段依赖上下文,长对话可能提炼不准。兜底:展示草稿 + 用户确认,可改可拒。
- **快照内容含敏感信息**(代码路径 / 决策细节) —— 但路径仍在 `~/.claude/code-mentor/`(用户本地),不进项目仓库,风险等价于现有 JOURNAL/DECISIONS。
- **会污染 `~/.claude/code-mentor/` 目录** —— 1 个文件 + 1 个目录,影响极小,跟现有 4 文件 + 1 子目录规模相当。
