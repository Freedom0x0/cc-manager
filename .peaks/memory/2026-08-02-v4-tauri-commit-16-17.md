## 关键决策 (D19)

### D19: v4.1 路线 A 完整闭环 (2026-08-02)

3 条教训:

1. **"删 mock" 类型 commit 必须 `git log -p <主入口文件>` 验证所有 import 链断**, 不能只 git rm 两个文件。commit 2 写 "删 src/mock.ts + mock-data.ts" 但 main.tsx 第 6 行 import 漏改 = D18 缺口。

2. **验证 commit 完整性的 3 步纪律**:
   - `cargo test --lib` 跑后端测试 (Rust 模块)
   - `npx tsc --noEmit` 跑前端类型检查
   - `npm run build:vite` 跑前端 production build (新加, 暴露 mock 缺口)
   3 步全过 = commit message 写的"删 / 改 / 加" 真正落地。D17 5 commit 序列只走前 2 步, D18 缺口是必然结果。

3. **端到端验证 (e2e) vs 单元测试**: e2e = vite dev server 起来 + curl http OK; 单元 = 类型 + 函数级。**e2e 不该被 "测试快" 优化掉** — 1 秒 vite dev server 启动 + 1 次 curl = 0 漏; 不做 = mock 缺口留 4 commit 才暴露。

## 经验教训

- **删 / 改 / 加 类 commit 必跑 build 验证** (不只是 test + typecheck)
- **入口文件 import 链 = commit 删除影响范围的真正定义** (主入口 main.tsx / App.tsx / 路由文件)
- **D18 "前端需改 N 处" 假象** — 实际只 1 处 (main.tsx), v4.0 早已走 tauri
- **vite dev server 起 + curl 是 5 秒 e2e**, 应纳入 commit 验证必跑项
